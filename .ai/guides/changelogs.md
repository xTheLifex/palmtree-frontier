# Guide: Changelogs

> How changes reach the in-game changelog in this repository.

## TL;DR

The in-game changelog is **client-side YAML only** — `Content.Client/Changelog/ChangelogManager.cs`
reads every direct `Resources/Changelog/*.yml` file and renders one tab per file. GitHub Actions can
generate entries into `Palmtree.yml` from merged PRs or from pushed commits that contain a `:cl:`
block; nothing else scans git history.

Existing files in this repo:

| File | Tab | Notes |
|---|---|---|
| `Resources/Changelog/Palmtree.yml` | Palmtree | **this fork's own entries** (`Order: -1`, first tab, ids from 90001) |
| `Resources/Changelog/Changelog.yml` | upstream | Wizden history, third-party |
| `Resources/Changelog/Frontier.yml` | Frontier | Frontier Station history |
| `Resources/Changelog/Maps.yml` | Maps | mapping changes |
| `Resources/Changelog/Admin.yml` | Admin | `AdminOnly: true` |

Palmtree entries go in `Resources/Changelog/Palmtree.yml`. It uses high ids (90000+) so the "new
changes" badge stays meaningful across the other files' id ranges. Tab title locale key:
`changelog-tab-title-Palmtree` in `Resources/Locale/en-US/_NF/changelog/changelog-window.ftl`.

## Entry format

Top-level fields: `Name` (tab name, defaults to the file name), `Order` (tab sort; lower is first),
`AdminOnly` (hide from non-admins). Entries:

```yaml
Entries:
- author: yourname
  changes:
    - type: Add        # Add / Remove / Tweak / Fix
      message: Adds a thing.
    - type: Fix
      message: Fixes another thing.
  id: 1                # unique, incrementing per file
  time: '2026-10-03T15:47:27.0000000+00:00'
```

## How the client reads it

- `ChangelogManager.LoadChangelog()` enumerates `/Changelog/`, keeps direct `*.yml` children
  (`Parts/` is ignored), deserializes `Changelog` (`Name`, `Entries`, `AdminOnly`, `Order`).
- Tabs sort by `Order`; tab title uses `changelog-tab-title-<Name>`.
- The window reloads YAML on every open (`ChangelogWindow.PopulateChangelog`), so a dev client shows
  edits immediately.
- `changelog_last_seen_<ServerId>` in client user data drives the "new changes" badge.

## Validation / automation

- CI validates changelog entries in PR bodies via `.github/workflows/nf-validate-changelog.yml`
  (`Tools/_NF/changelog/validate_changelog.js`).
- **Merged PRs**: `.github/workflows/changelog.yml` runs `Tools/_NF/changelog/changelog.js` on PR
  close and appends the `:cl:` block from the PR body to `Palmtree.yml` (it used to target
  `Frontier.yml`). Falls back to `GITHUB_TOKEN` when `BOT_TOKEN` is unset.
- **Direct commits**: `.github/workflows/commit-changelog.yml` runs
  `Tools/_NF/changelog/commit_changelog.js` on every push to `master` and appends entries from
  commit messages that contain a `:cl:` block. Commits generated by PRs
  (`Merge pull request ...` / subject ending in `(#123)`) are skipped so entries are not duplicated.
- Both scripts **append** to the file and preserve top-level `Name`/`Order`/`AdminOnly`; keep that
  behavior when editing `writeChangelog`.
- Never append Palmtree entries to the upstream history files.

## Checklist

- [ ] Entry added to `Palmtree.yml` (or let a `:cl:` block generate it).
- [ ] Unique `id`, sensible `author`, ISO `time`.
- [ ] `type` is one of Add/Remove/Tweak/Fix.
- [ ] PR body / commit message uses `:cl:` with `- add|remove|tweak|fix: message` lines.
- [ ] YAML validates (`nf-validate-changelog` workflow or run the validator locally).
